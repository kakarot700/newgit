# NewGit 0.1.0

**Status: Production Candidate (pre-1.0), not Production Ready.** NewGit is an agent-native version-control system for software developed by people and AI agents. It records goals, candidate changes, evidence, evaluations, approvals, and integration decisions alongside repository history.

## Highlights

- Rust CLI and SHA-256 content-addressed object store with snapshots, workspaces, status/history, tree and line diffs, three-way merges, integration, rollback, integrity verification, and deliberately non-destructive garbage collection.
- First-class goals, changes, evidence, evaluations, and proposals with lifecycle checks and human-approved integration.
- Optional self-hosted HTTP/1.1 + JSON remote with bearer-token roles, audit records, and NewGit push/pull; read-only embedded web UI and MCP stdio server.
- Git repository import/export using the installed `git` executable's `fast-export`/`fast-import` streams.
- Locked dependency set, committed deterministic SBOM, dependency/advisory gates, CodeQL workflow, CI release packaging, and checksum verification.

## Build from source

```bash
git clone https://github.com/kakarot700/newgit.git
cd newgit
cargo build --release --locked
cargo test --locked
cargo test --release --locked
```

The toolchain file pins Rust 1.99.0. `Cargo.toml` declares Rust 1.80 as the package minimum, but CI does not separately test that minimum.

## Git interoperability boundaries

Import/export are whole-history conversion paths, not a Git smart-HTTP remote. NewGit does not claim full Git compatibility. Submodules are refused; annotated tag metadata cannot be represented exactly; selected ref, path, and message edge cases are lossy or skipped with a report. See [Git compatibility](../GIT_COMPAT.md) and [known limitations](../../KNOWN_LIMITATIONS.md) before relying on conversion.

## Platform and deployment limits

The prebuilt distribution targets **Linux x86_64 GNU**. Other operating systems and architectures have not been claimed as verified. Protocol v1 uses plain HTTP: place a server behind a TLS-terminating reverse proxy or use a trusted tunnel; the current CLI client does not implement HTTPS. Evaluate the documented threat model and operational limits before production deployment.
