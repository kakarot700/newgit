# Git compatibility matrix

**Scope:** this matrix covers NewGit's one-shot `import-git` / `export-git` conversion and the separate Git smart-HTTP upload-pack adapter plus a deliberately narrow receive-pack branch-update slice. It does not imply Git SSH support or blanket Git compatibility. Each claim is limited to the real-Git tests named in its evidence.

## Status meanings

- **SUPPORTED** — the specific behavior stated in the row has a passing automated test using real Git input/output. This is a bounded test claim, not a claim of complete Git compatibility.
- **PARTIAL** — tests cover a stated subset, while an important portion of the feature is known to be absent, lossy, or unverified.
- **LOSSY** — conversion is known to discard or change part of the Git representation.
- **UNSUPPORTED** — there is no conversion support for the feature; relevant refs/data may be omitted and reported.
- **REFUSED** — the importer rejects the input with an error rather than importing a misleading representation.
- **NOT TESTED** — no automated Git interoperability test establishes behavior for this feature. Code paths or prose documentation alone are not treated as proof of support.

## Feature matrix

| Git feature | Status | Evidence and boundary |
|---|---|---|
| Git smart-HTTP protocol v0/v1/v2 (upload-pack) | **SUPPORTED** (bounded) | A black-box test uses the installed Git 2.43.0 CLI against a live NewGit-backed HTTP server: v2 `clone` and `ls-remote`, v0 `fetch`, v1 `pull`. The test checks HTTP bearer-token access, refs, the checked-out commit/tree, and actual binary/text blob bytes. It does not establish other Git versions/platforms or a minimum Git version for the adapter. `tests/git_remote_e2e.rs::real_git_clone_fetch_pull_push_and_ls_remote_over_smart_http`. |
| Git push / receive-pack | **PARTIAL** (bounded branch slice) | Real Git 2.43.0/Linux pushes a first branch into an empty NewGit repo, fast-forwards existing branches, and creates branches in ordinary and `--atomic` multi-ref requests, then independently clones/fetches and checks canonical refs and file bytes. The write-role bearer token is required. The server advertises `atomic`; a successful atomic multi-ref push updates the requested canonical refs together, while an atomic push with a forced non-fast-forward policy failure changes neither refs nor canonical object inventory. An ordinary mixed projection result returns HTTP 409 and leaves refs and object inventory unchanged. A multi-ref CAS race proves only one complete ref set and its staged objects are promoted. Tags, deletions, malformed packets, signed pushes, and forced non-fast-forwards remain refused. Protocol versions other than tested v0 push, Git-over-SSH, SHA-256 Git wire repositories, and additional versions/platforms are not supported or established. `tests/git_remote_e2e.rs::real_git_clone_fetch_pull_push_and_ls_remote_over_smart_http`, `::real_git_initial_push_to_empty_newgit_repo_creates_main`, and `tests/txn_recovery.rs::precommit_object_staging_is_skipped_on_cas_failure`, `::racing_multi_ref_pushes_publish_only_one_complete_ref_set`. |
| Ambient Git environment/template hooks | **MITIGATED** (targeted) | Exporter commands use an empty private template directory and clear repository/config redirection variables. A black-box test runs the server with hostile `GIT_DIR`/`GIT_WORK_TREE`/`GIT_TEMPLATE_DIR`, forces detached checkout with a malicious `post-checkout` sentinel hook, proves Git `ls-remote` reads NewGit refs, and verifies the sentinel bare repository and hook marker remain unchanged. Other injected variables are not individually tested. `tests/git_remote_e2e.rs::ambient_git_environment_cannot_redirect_or_run_template_hooks`. |
| Git export, upload-pack, and receive-pack wall-clock work | **BOUNDED** (targeted) | A 120-second absolute request deadline covers projection/export and the Git subprocess, including receive-pack. Unix process groups are force-killed and the direct child is reaped. The utility regression proves descendant termination; ordinary Git CLI integration proves the normal path. Windows process-tree timeout behavior is not tested. `src/util/process.rs::deadline_kills_and_reaps_child_process_group`. |
| Git smart-HTTP response size | **BOUNDED** (targeted) | The same real-repository integration fixture calls the adapter with a 64-byte total advertisement limit and asserts it returns `Error::Limit` instead of sending a larger payload. `tests/git_remote_e2e.rs::real_git_clone_fetch_pull_push_and_ls_remote_over_smart_http`. |
| Git smart HTTP over HTTPS | **NOT TESTED** | The built-in server is plain HTTP; standard Git clients may connect through a TLS-terminating reverse proxy, but that deployment path is not exercised by the loopback test. |
| Blobs | **SUPPORTED** | Real-Git tests compare imported blob bytes against `git cat-file`; export round-trip also compares Git blob object IDs for the tested fixture. This does not make NewGit's internal object ID a Git blob ID. `tests/git_compat.rs::import_matches_git_content_exactly` (lines 229–369) and `::export_roundtrip_matches_git` (386–499). |
| Trees | **SUPPORTED** | The tested histories preserve per-commit paths, file modes, and file bytes through import/export. Tests compare the resulting trees by entries and blob IDs, not by asserting every Git tree object ID. Same tests as above. |
| Commits | **SUPPORTED** (semantic) | The fixture checks imported commit count, messages, author metadata, timestamps/time zones, parent counts, and merge-parent order; export checks commit count, author/committer metadata, messages, and first-parent history. Real-Git cases cover an octopus merge and a merge whose second parent is already an ancestor of its first, preserving ordered parents. Commit-object hash identity is **not** asserted. `tests/git_compat.rs::import_matches_git_content_exactly`, `::export_roundtrip_matches_git`, `::merge_with_redundant_ancestor_parent_exports_in_topological_order`, and `::octopus_merge_preserves_parent_order_and_trees_across_roundtrip`. |
| Octopus merges | **SUPPORTED** (semantic) | A real Git fixture creates a four-parent octopus merge and round-trips it through Git → NewGit → Git → NewGit. It asserts all four ordered parents in NewGit metadata, the exported Git parent order and paths/modes/blob IDs, then the reimported four-parent order and deep integrity. Evidence is limited to Git 2.43.0/Linux; commit and tree object IDs are not generally claimed to match. `tests/git_compat.rs::octopus_merge_preserves_parent_order_and_trees_across_roundtrip`. |
| Git SHA-256 repositories (semantic import/export) | **SUPPORTED** | A real `git init --object-format=sha256` two-commit repository imports with its 64-hex source commit IDs recorded in `extras.git_oid`, then exports with matching refs, commit count, paths, modes, and blob bytes. The destination uses Git's default object format; Git object IDs are not claimed to match. Evidence: `tests/git_compat.rs::sha256_git_import_export_roundtrips_semantically`, Git 2.43.0/Linux. |
| Lightweight tags | **SUPPORTED** | A real lightweight tag is imported as a ref and survives export with the referenced tree. The rich fixture creates `light-tag`; import checks the ref and the round-trip checks its tree. `tests/git_compat.rs` (138–139, 229–269, 386–425). |
| Annotated tags | **LOSSY** | The tag ref is kept but its tagger/message metadata is stripped; export can only recreate a lightweight tag. Real-Git tests check the unsigned annotated-tag report and ref survival, plus the signed-tag case's report, target tree, and lightweight export. `tests/git_compat.rs::ssh_signed_annotated_tag_loss_is_reported_and_exported_as_lightweight` and the rich fixture. |
| Tag objects | **LOSSY** | NewGit has no Git tag-object representation: an annotated tag becomes a ref to its target snapshot, not a preserved tag object. The signed-tag regression verifies Git accepts the source signature, checks the tag ref is reported as stripped, and confirms export produces a lightweight tag; tag-object bytes are not preserved. `tests/git_compat.rs::ssh_signed_annotated_tag_loss_is_reported_and_exported_as_lightweight`. |
| Non-commit Git refs (including tags to blobs/trees) | **REFUSED** | Before `fast-export`, the existing `for-each-ref` scan checks the direct or peeled target type and refuses ordinary, non-skipped refs that do not target commits; the error names the ref and object type, and refs are not moved. A real-Git test covers lightweight and annotated refs to reachable/orphan blobs, tree tags, and a tag-only source. Nested annotated-tag chains, non-tag non-commit refs, other Git versions, and other platforms are not separately tested. `tests/git_compat.rs::non_commit_git_refs_are_refused_atomically`; `src/gitio/import.rs::scan_git_refs`. |
| Signed tag objects/signatures | **LOSSY** | A real SSH-signed tag is verified by Git before import. On Git 2.43.0/Linux, `fast-export --signed-tags=strip` still emits the SSH signature payload in tag data; NewGit then drops it while flattening the annotated tag to a direct snapshot ref. The tag ref appears in `ImportReport.annotated_tags_stripped`, and export creates an unsigned lightweight tag. NewGit does not preserve or verify tag signatures. OpenPGP/X.509, other Git versions, and other platforms are not established. `tests/git_compat.rs::ssh_signed_annotated_tag_loss_is_reported_and_exported_as_lightweight`. |
| Signed commits | **LOSSY** | Git 2.43.0 `fast-export` drops commit `gpgsig` headers. Import scans original commit objects and reports affected source IDs in `signed_commits_stripped`; NewGit neither preserves the signature bytes nor verifies them, and export creates unsigned commits. A real SSH-signed commit is verified by Git before import; the test checks the signature in the raw source object, its absence from the stream and exported object, the exact report ID, and deep NewGit integrity. Evidence is limited to one SSH signature on Git 2.43.0/Linux; OpenPGP, other Git versions, and alternate signature-header formats are not established. `tests/git_compat.rs::signed_git_commit_signature_loss_is_reported`; `src/gitio/import.rs::list_signed_commits`; `docs/GIT_COMPAT.md` hard limitation 11. |
| Symbolic `HEAD` | **SUPPORTED** | The real-Git fixture's symbolic `HEAD` pointing at `refs/heads/master` is mapped on import and restored on export. This claim covers ordinary symbolic `HEAD`, not all Git symbolic-ref use. `tests/git_compat.rs::import_matches_git_content_exactly` and `::export_roundtrip_matches_git`. |
| Detached `HEAD` | **SUPPORTED** | Real Git tests cover a repository whose only reachable commit is a detached `HEAD`, a detached successor ahead of a named branch, and nested branch names that collide with successive temporary-ref candidates. Import stores the direct NewGit `HEAD` without importing fast-export's pseudo-ref `HEAD`; export reconstructs detached checkout state and removes its temporary ref. `tests/git_compat.rs::detached_head_only_history_roundtrips_without_pseudo_refs`, `::detached_head_ahead_of_branch_roundtrips_without_moving_branch`, and `::detached_head_export_avoids_nested_named_ref_collision`. |
| Non-`HEAD` symbolic refs | **UNSUPPORTED** | NewGit refs are direct object pointers. Real Git `for-each-ref` lists non-`HEAD` symbolic refs, but Git 2.43.0 `fast-export --all` omits them. Import pre-scans with `for-each-ref`, skips and reports these names, and does not map them as ordinary refs. The fixture covers two `refs/heads/*` aliases to `refs/heads/master` and confirms ordinary symbolic `HEAD` is retained; other namespaces/targets and Git versions are not established. The scan and export are separate commands, so concurrent source-ref mutation is unsynchronized and untested. `tests/git_compat.rs::non_head_symbolic_refs_are_reported_and_not_imported`; `src/gitio/import.rs::scan_git_refs`. |
| Ref-name mapping collisions | **REFUSED** | Distinct NewGit names such as `main` and `refs/main` both map to Git's `refs/heads/main`; export now detects this and returns an error before initializing the target instead of silently dropping a ref. `tests/git_compat.rs::export_refuses_colliding_git_ref_names_without_partial_output`. |
| Git reflogs | **UNSUPPORTED** | Git reflog entries are not part of the import/export mapping; NewGit's own transactional reflog is a separate internal facility and is not evidence that Git reflogs round-trip. The Git interoperability suite has no reflog-transfer test. See the stream-only import/export paths in `src/gitio/import.rs` (111–140, 391–429) and `src/gitio/export.rs` (70–103, 142–204); contrast NewGit's local reflog API in `src/repo/refs.rs` (167–169). |
| Git notes | **UNSUPPORTED** | `refs/notes/*` are intentionally skipped and reported. The real-Git fixture creates a note and asserts both the skip report and absence of the notes ref in NewGit. `src/gitio/import.rs` (55–63); `tests/git_compat.rs` (149, 229–263); `docs/GIT_COMPAT.md` (44–47). |
| Reporting skipped refs omitted by `fast-export` | **SUPPORTED** (reporting only) | The importer seeds `refs_skipped` from the `for-each-ref` scan for configured unsupported ref families, rather than depending only on stream events. A real Git 2.43.0/Linux fixture gives blob targets to `refs/remotes/origin/orphan-blob` and `refs/notes/probe/orphan-blob`; `fast-export --all` omits both, but import reports both and writes neither ref. Namespace blob-ref reporting is separately covered. Other Git versions/platforms and every internal ref family with non-commit targets are not established. `tests/git_compat.rs::omitted_unsupported_blob_refs_are_reported_from_the_ref_scan`; `src/gitio/import.rs::scan_git_refs`. |
| Replace refs | **UNSUPPORTED** | NewGit does not represent replacement overlays. A real Git fixture proves default `fast-export --all` applies a replacement commit's message/tree while traversing an ordinary branch; import now runs fast-export with `GIT_NO_REPLACE_OBJECTS=1`, reports/skips the `refs/replace/<object>` ref, and imports the stored original branch history instead. The test checks the original target message/tree, descendant tree, skipped-ref report, and deep verification. This preserves stored objects, not the replacement-aware view shown by ordinary Git commands. Evidence is limited to Git 2.43.0/Linux. `tests/git_compat.rs::replace_refs_do_not_rewrite_imported_branch_history`; `src/gitio/import.rs` fast-export environment override. |
| Git namespaces | **UNSUPPORTED** | Physical refs under `refs/namespaces/<namespace>/...` are skipped and reported on both import and export rather than being mis-mapped to ordinary branches. A real Git 2.43.0/Linux fixture proves `GIT_NAMESPACE=tenant git ls-remote` sees virtual branch/tag/blob refs; `fast-export --all` emits commit-target refs but omits the namespace ref to a blob. The `for-each-ref` scan reports all three namespace refs, including the omitted blob ref, and export does not leak a NewGit namespace-shaped ref as an ordinary branch. Namespace-only commit history may still be streamed/imported as unreachable objects, so this is not a confidentiality boundary. The scan and stream are separate invocations; concurrent source-ref mutation is not synchronized. Namespace-preserving import/export and other Git versions/platforms are not established. `tests/git_compat.rs::git_namespace_refs_are_reported_and_not_exported_as_branches`; `src/gitio/import.rs::scan_git_refs`, `::skip_ref`; `src/gitio/export.rs::export_git`. |
| Gitlinks | **REFUSED** | A mode `160000` gitlink aborts import with an actionable error. The real submodule test verifies the error, zero refs moved, and repository integrity. `src/gitio/import.rs` (206–215, 462–483); `tests/git_compat.rs::submodule_import_is_refused_atomically`. |
| Submodules | **REFUSED** | Submodules are not represented as nested repositories; import fails atomically rather than fabricating support. Same passing refusal test as the gitlinks row. `docs/GIT_COMPAT.md` (78–84). |

A separate Git-plumbing fixture creates a raw commit with invalid UTF-8 bytes (porcelain `git commit` normalizes them on Git 2.43.0); Git `cat-file` and `fast-export` retain the source bytes, while NewGit import uses the documented replacement text and sets `extras.git_message_lossy=1`, and export contains only that converted UTF-8 text. | Executable modes | **SUPPORTED** | The fixture sets an executable bit with Git, compares mode `100755` on import/export, and checks the resulting tree. `tests/git_compat.rs` (71–74, 172–179, 279–304, 412–424). |

## Exact Git objects versus semantic repository compatibility

These are different guarantees. **Exact Git object compatibility** means that the relevant serialized Git object bytes—and therefore its Git object ID under the repository's object hash format—are preserved. **Semantic repository compatibility** means that the converted repository retains the tested content and behavior, such as file bytes, modes, refs, commit metadata, and ancestry, even if its internal representation or object IDs differ.

NewGit computes internal object IDs as SHA-256 over its own canonical object encoding (`src/object/id.rs` lines 1–35; `docs/STORAGE_FORMAT.md` §1). Git import stores source commit IDs in format-neutral `extras.git_oid` metadata (and also uses legacy `extras.git_sha1` for SHA-1 repositories), but NewGit snapshot IDs are not Git commit IDs. The tests establish exact Git blob IDs for the tested SHA-1 export round-trip and semantic commit/tree/history equivalence for the tested SHA-256 fixture; they do **not** establish preservation of SHA-256 object IDs or general Git commit/tree ID equality. Annotated tag objects, signatures, reflogs, and omitted refs remain outside the round-trip guarantee.

## Test and CI evidence

The interoperability tests use the installed `git` executable to generate repositories and inspect results. On this checkout, `git --version` reported **2.43.0**. The latest real-Git suite includes SSH-signed-tag loss checks, unsupported refs omitted by `fast-export`, and a raw invalid-UTF-8 commit-message loss check; final local suite counts are recorded in `PROJECT_STATE.md`. Exact-SHA hosted CI and CodeQL links are delivered with the task completion after the single push. CI runs debug and release tests on Ubuntu 24.04 and requires Git >=2.34.0 plus `ssh-keygen`, so hosted runs cannot silently pass while skipping SSH-signature fixtures. CI does not define a broader Git-version or operating-system compatibility matrix. Evidence is limited to tested conversion cases on the exercised Linux/Git environment; concurrent source-ref mutation during the separate ref scan and export remains untested.
